# 利润测算表

默认显示当前账号租户下已保留商品，每个子 ASIN 独立一行。商品库进入指定商品测算时允许只查看该商品，返回后恢复已保留列表。

行内支持售价、FBA、仓租、头程单价、供货价、供应商链接和佣金比例；公共假设在表格上方折叠设置，明确应用到当前页。参数不完整显示待补充，不假设免费或虚构汇率。修改后自动试算，点击保存修改才新增持久化方案；原方案、报价及模板保留在参数 / 历史。

体积重 = 包装长宽高（厘米）乘积 / 用户输入体积系数。计费重取包装实重（千克）和体积重最大值；头程为计费重乘人民币每千克单价。参数缺失不自动填零。人民币利润由未舍入美元利润乘汇率后最终舍入；精度由 Go 有理数运算保障，前端仅展示。

新增 GET /api/ecom/screening/profit/products，内部对应 /api/v1/screening/profit/products。支持分页10/20/50/100、关键词、明确商品范围及白名单排序；派生字段按完整结果排序后分页，缺失值置后。严格沿用租户身份校验，未新增数据库表，扩展现有利润方案输入输出快照。

Modern Web Guidance：采用 responsive-table（“Give the wrapper a role=region attribute”）、sortable-table（排序标题使用按钮）和 forms。表格独立滚动、支持键盘访问及列宽调整；保留原生按钮和对话框焦点行为。按用户要求保持逐行表格，不切换商品卡片。TanStack Table 不交由 React Compiler 自动记忆化。

验证：Go单元、真实隔离PostgreSQL查询/排序/隔离测试，Web类型检查与生产构建，隔离浏览器行内试算/保存/历史与页面溢出检查。运行环境更新不修改现有商品费用或人工结论。

## 自动物流和仓租

参考选品资料库 public/profit-values.mjs、profit-specs.mjs 和 profit-storage.mjs：体积系数默认5000，头程9 CNY/kg，可修改；保留旧方案手填头程。仓租优先手填，其次原始来源金额，最后按普通非危险品美国站基础仓租估算。默认在库30天，按洛杉矶当前月份选择标准尺寸0.78/2.40、大件0.56/1.40 USD/ft³/月（1–9月/10–12月），乘包装体积及在库天数/当月天数。包装分段优先原始字段，否则按18×14×8英寸及20磅判断。缺失必要尺寸重量时不当作零成本。

此为基础仓租估算，不含库龄、仓储利用率及危险品附加费；费率快照版本、月份和在库天数随新方案保存，旧方案不回写。来源：https://sellercentral.amazon.com/gp/help/external/G3EDYEF6KUCFQTNM 。UI采用forms指南的“use visible labels”，在库天数和自动/手填状态保持可见。

## 自动佣金

迁入选品资料库 profit-referral.mjs 的美国站类目费率、别名和特殊类目优先规则，快照保存于 data/referral_rules.json，核对来源 https://sell.amazon.com/pricing （2026-11-22）。默认按类目路径匹配；未知类目保持待匹配，可在行内选择收费类目。新方案佣金比例缺失时自动匹配，旧方案有手填比例时保持手填；改售价后自动重算，恢复自动可回到类目规则。

计算含整价档位、分段金额及最低佣金，分段加权使用Go精确有理数，不使用前端四舍五入比例扣费；保本售价按各档和最低佣金分支求解并验证。输出保存匹配类目、规则版本、名义比例和实际佣金。零手填比例保持有效，不强制最低佣金；最低佣金只用于自动规则。

forms指南：使用明确类目标签及自动/手填文字状态；不因切换收费类目直接持久化，仍点击保存修改才新增快照。

## 行内自动保存

利润表输入停止800毫秒后自动保存，离开当前行或浏览器转入后台时立即尝试保存。页面展示保存状态、失败重试及参数/历史，不再要求点击保存修改。单个ASIN串行保存，整体最多3个并发；保存过程可以继续编辑，较旧响应不会覆盖新草稿。翻页时后台队列继续执行；离开页面后的保存仍刷新缓存，使返回后读取已提交内容。未完成保存时关闭或刷新浏览器会提示。

网络失败保留当前草稿，重试沿用原Idempotency-Key；费用不完整仍可保存快照，非法格式不写入。请求绑定原租户；历史方案继续追加。完整多方案编辑器保留原操作。

验证：apps/web 下 npm run test:profit-autosave；隔离浏览器 TestBrowserProfitTable 验证供货价70改71后自动持久化、利润421.70 CNY、历史两条，无需点击保存。forms指南采用“announce AJAX submission results”状态反馈；按用户要求自动保存输入，类目切换也参与自动保存。

## 利润排序性能

派生列先只读取全量匹配商品的公式输入，使用精确计算完成排序，再拉取当前页详情；比较键每行只解析一次。列表方案不携带完整来源/商品/月数据快照，specs仅省略legacy_site_snapshot，其他商品规格保留。历史来源仍保留在数据库及详情/历史接口。统计查询只使用筛选实际需要的关联。升降序均将缺失值置后、ID稳定排序。

已用真实隔离PostgreSQL验证全量排序后分页、租户隔离及来源保留；运行库对照优化前升降序前100项的ID、输入和测算输出完全一致。
